  ordered stop IDs. `ReachVoyageDirector.ts` checks production order and
  reverses at WOH G64, then at Earth, making 126 travel legs per round trip.
  The active leg, completed distance, direction, and round trips are in the
  checkpoint. `test-reach-v4.mjs` exercises all 64 stops, reversal, migration,
  reload, odometer accounting, and 126 legs.
- Proven by code: the native `JourneyReset.IsFreshCheckpoint` accepts version
  6 and requires a fresh Earth observation with zero odometer and no active
  leg. The removal and confirmation use the shared localStorage key. The
  checkpoint validation fixture and the isolated WebView2 reset fixture passed.
- Proven by code and focused fixtures: primary display publishes the voyage
  pose and composition shift; followers copy them. HUD distance and speed
  formatting and Solar System orbit visibility passed focused tests. Physical
  three-monitor presentation is still an owner acceptance gate.
- Owner-reported, not independently measured here: the approximate 157,586
  light-year distance to WOH G64. The source routes to that object, but it
  derives the object's location from a galaxy-plane intersection rather than
  a literal distance field in its landmark record. Public copy labels the
  precise distance as an owner estimate.

without `-Apply` is the package completeness rehearsal; do not use an owner

The fixed build ID identifies cache-busted unhashed web assets, not a

## Approval gates

1. Review the final source and documentation diffs, including the 1.1.0
   installer metadata and the retained upgrade namespace. Record the exact
   local commits used for packaging.
2. Build a self-contained host publish and a clean, complete offline stage
   from final immutable source commits. Verify every asset and license,
   attribution text, manifest, build identity, and SHA-256. Run the package
   completeness rehearsal on that stage.
3. Compile the Inno installer with the confirmed Inno Setup 7.1 installation.
   Inspect version resources and output name. Rehearse fresh install, upgrade
   from v1.0.0, recovery/rollback, uninstall, and backup preservation with
   isolated fixtures. Test primary-only and three-monitor behavior, Settings,
   preview isolation, Reset Trip, checkpoint restoration, and native input
   exit without touching the working installation or saved journey.
4. Obtain complete 64-stop playback evidence and the owner's final physical
   one-monitor and three-monitor visual acceptance. Automated and native
   smoke tests do not substitute for this gate.
5. The human owner alone executes any branch promotion, push, tag, GitHub
   Release and attachment upload, or deployment after reviewing the local
   commits and the workflow version on each branch. Preserve the current
   working install, journey, profiles, imagery cache, and backups.
